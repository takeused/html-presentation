# Briefing Lecture Presentation

흰 배경 강의형 "데이터 브리핑" 덱을 만드는 스킬이다. 레퍼런스는 조코딩 AI 리터러시 특강 1편(youtube AHlWV-nI9yo)의 발표 화면이다.
이 스킬 폴더의 `template.html`을 복사해서 맨 아래 `DECK` 객체만 채우면 된다. 아래에서 `<스킬 폴더>`는 이 SKILL.md가 있는 폴더다(전역 설치 시 `~/.claude/skills/briefing-lecture-presentation`). 사진·아이콘 CDN이 필요 없고, 폰트(Pretendard)만 불러온다.

## 1. 스타일

- **파트 표지(part)**: 딥 네이비→블루 그라디언트 위에 얇은 격자선과 큰 원 두 개. `Part 1 · 3클립` 작은 글씨, 블루 그라디언트 `Part 1.`, 흰 대제목, 좌하단 로고·연락처. 마무리 장도 이 레이아웃을 쓴다.
- **목차(contents)**: 흰 배경, 왼쪽 `Contents`, 오른쪽 01~0N 번호 목록과 회색 태그.
- **섹션 구분(section)**: 거의 검정 배경, 블루 번호, 흰 대제목, 회색 보조 두 줄.
- **본문 공통**: 흰 배경. 좌상단 파란 아이브로우(`PART 1. …`), 제목은 가는 글씨로 시작해 핵심만 `<b>`로 굵게. 아래쪽에 회색 출처 줄(`src`)과 굵은 결론 한 줄(`take`). 맨 아래 챕터 바(현재 챕터만 진회색으로 채움)와 페이지 카운터.
- 강조색은 하나(기본 `#2f62f0`→`#4cc3f5` 그라디언트). 강조 카드나 강조 막대는 한 장에 하나~둘만 쓴다.

## 2. 제작 순서

1. 주제와 분량을 확인한다. 기본은 10~15장, 챕터 3~4개, 표지 1장 + 목차 1장 + 챕터마다 섹션 1장 + 마무리 1장이다. 챕터마다 본문이 2장 이상 되게 나눈다(본문 1장짜리 챕터는 섹션 장이 더 커 보인다).
   - 근거 수치를 어디서 가져올지 정해지지 않았으면 사용자에게 묻는다(웹 조사 / 사용자가 준 자료 / 수치 최소화). 조사 방법은 4-1을 따른다.
   - "후속편", "다음 편"을 요청받으면 4-2를 따른다.
2. `const DECK = { ... };` 블록만 담은 데이터 파일(예 `deck.js`)을 쓴다. `brand{name, contact}`, `eyebrow`, `accent`, `accent2`, `chapters[]`, `slides[]`를 채운다. 엔진 CSS와 렌더링 엔진 블록은 고치지 않는다.
3. 조립 스크립트로 덱 파일을 만든다. 템플릿의 DECK 자리에 데이터를 넣고, 첫 줄 주석을 `<!-- 브리핑 강의형 발표자료: <제목> (<N>장) -->`로, `<title>`을 덱 제목으로 바꿔 준다.
   ```bash
   python -I <스킬 폴더>/scripts/build_deck.py <스킬 폴더>/template.html deck.js <주제>_briefing_presentation.html "<덱 제목>" <N>
   ```
   데이터를 셸 heredoc으로 직접 넘기면 한국어 따옴표·「」·백틱 때문에 셸이 깨지기 쉽다. 데이터는 파일 쓰기 도구로 저장하고 스크립트에 경로로 넘긴다. 고칠 때도 deck.js를 고치고 다시 조립한다.
4. 검증한다(5장 참고).
5. 작업 폴더에 발표 허브 `index.html`(DECKS 배열)이 있으면 맨 위에 등록한다. `id`는 기존과 겹치지 않게 짓고 `isCinematic: false`로 둔다.

## 3. 레이아웃 7종 (slides[].layout)

| 레이아웃 | 필드 | 메모 |
|---|---|---|
| part | kicker, part, title, sub? | 표지·마무리. 챕터 바 없음 |
| contents | tags[]?, items[]? | items를 비우면 `DECK.chapters`를 쓴다 |
| section | chapter, title, meta[], num? | num을 비우면 챕터 번호(01…) |
| split | chapter, title, left, right, src, take | 좌측 카드 + 우측 표/선택지 |
| bars | chapter, title, items[{label, value, unit, em, show?}], src, take, h? | 막대 높이는 `value`의 최댓값 기준 비례(기본 300px). 강조 막대만 `em`. 화면 숫자는 `show`(없으면 `value`)와 `unit` |
| quotes | chapter, title, items[{quote, desc, by}], src, take | 카드 2개. 인용은 「」로 감싼다 |
| cards | chapter, title, items[{value, unit, label, desc}], src, take | 수치 카드 3개. `value`에 `'10 → 58'`, `'67 : 32'` 같은 비교도 쓸 수 있다(`unit: ''`) |

`split`의 좌우 블록은 다음 중 하나다.

- `left: { type: 'metric', value, unit, label, desc }` 큰 그라디언트 수치
- `left: { type: 'text', head, paras[] }` 개념 설명
- `right: { type: 'table', cols, head[], rows[][], val }` `cols`는 CSS grid 열 너비(예 `'1.6fr .6fr 1fr'`), `val`은 파란 값 열 번호(0부터)
- `right: { type: 'options', items[{k?, t, d?, em}] }` 세로 선택지 카드, `em`인 카드 하나만 진파랑. 작은 라벨 `k`에 연도(`2016`)나 순번(`01`, `02`, `03`)을 넣으면 연표나 단계 목록으로 쓸 수 있다

- 막대그래프의 `value`는 높이 계산용이라 모든 막대가 같은 단위여야 한다. 화면에는 읽기 쉬운 단위로 `show`와 `unit`을 따로 준다(예 `{ value: 718.8, show: '12', unit: '시간' }`, `{ value: 7, show: '7', unit: '분' }`). 4분에서 17시간처럼 기하급수로 커지는 값은 앞쪽 막대가 최소 높이(24px)로 눌려 보이는데, 증가 폭을 보여 주려는 것이면 그대로 두고 배가 주기는 `src`나 `take`에 적는다.

## 4. 규칙

- 폰트는 jsDelivr Pretendard만 쓴다. Google Fonts에는 Pretendard가 없어서 바꾸면 조용히 시스템 폰트로 바뀐다.
- 문자열 안에는 `<br>`, `<b>`, `<em>`만 쓴다. 백틱은 쓰지 않는다.
- 제목은 한 줄(약 32자 이내)을 기본으로 한다. 길면 `<br>`로 두 줄까지 쓰되 본문 공간이 줄어든다.
- 한 줄로 끝나야 하는 글자는 짧게 쓴다. 저절로 두 줄이 되면 마지막 단어 하나만 아랫줄에 남아 어색하다.
  - 설명 카드 제목(`text.head`)은 14자 안팎. 길면 짧은 이름만 남기고 정의는 첫 문단으로 옮긴다(예 `ARC-AGI-3`).
  - 선택지 문장(`options.t`)은 22자 안팎, 수치 카드 라벨(`cards.label`)은 14자 안팎, 큰 수치 아래 설명(`metric.label`)은 18자 안팎(영문·숫자가 섞이면 조금 더 들어간다).
- 막대그래프(`bars`)는 7개까지 넣는다. 7개가 쓸 수 있는 폭(1632px)을 거의 다 채우므로 8개 이상이면 넘친다. 모델명·날짜처럼 긴 라벨은 `'Gemini 3.1 Pro<br>2026.3'`처럼 두 줄로 나눈다.
- 카드 설명·인용 설명은 자동 줄바꿈되지만, 의미 단위로 `<br>`을 넣어 줄 끝을 맞추면 레퍼런스처럼 단정해진다. 막대 라벨(`.bcol .lb`)은 nowrap이라 길면 `<br>`로 나눈다.
- 모든 수치에는 `src`에 출처를 단다. 지어낸 숫자는 쓰지 않고, 확인 못 한 숫자는 사용자에게 묻는다. 인용을 원문 그대로 옮길 수 없으면 "요지"라고 밝힌다.
- 영상·기사·남의 발표 내용을 바탕으로 만든 덱이면 표지 `brand.contact`에 원 자료를 밝힌다(예 `자료 출처 · ○○ 특강 1편(2026)`). 원 자료에 나온 수치는 원 자료가 단 출처를 `src`에 그대로 옮긴다.
- 학습 시점 이후 사건이라 직접 검증할 수 없는 수치는 출처와 함께 옮기되, 검증하지 못했다고 사용자에게 알린다.
- 수치를 잘못 읽기 쉬운 지점은 `src`에 짧게 적는다. 예: 상관이지 인과가 아님, 회사마다 측정 기준이 달라 직접 비교 어려움, 상대 점수라 합이 100이 아님, "50% 확률로 성공하는 길이"처럼 지표의 정의.

### 4-1. 근거 수치 조사 (웹 조사를 고른 경우)

- 1차 출처를 우선한다. 순서는 원 데이터 파일(예 METR `benchmark_results_*.yaml`) → 기관 보고서·논문 원문 → 회사 공식 블로그·실적 발표 → 언론 보도 → 2차 요약 블로그다.
- 검색 결과 요약이나 2차 블로그의 수치는 그대로 쓰지 않는다. 원문 페이지를 열어(WebFetch, 데이터 파일은 curl로 받아 파싱) 수치·조사 규모·기간·정확한 표현을 확인한다.
- 원문을 열 수 없어 보도로만 확인한 수치는 `src`에 원 출처(예 `구글 블로그(2026-04-22)`)를 적고, 보도로만 확인했다고 사용자에게 알린다.
- 원문도 믿을 만한 보도도 못 찾은 수치(예 팟캐스트 발언만 돌아다니는 수치)는 넣지 않는다.
- 조사 없이 학습 지식으로 넣은 수치는 따로 모아 사용자에게 알린다.
- 같은 지표가 판마다 달라지면(예 13% → 15% → 19%) 최신판을 쓰고, 이전 값은 추세로 보여 준다.
- 마치면 확인 경로(원문 / 보도 / 학습 지식 / 제외)별로 나눠 사용자에게 보고하고, 쓴 출처 URL을 함께 준다.

### 4-2. 후속편 (Part 2, Part 3 …)

- 앞 편 덱 파일을 열어 `brand`, `accent`, `accent2`, 챕터 구성 방식을 그대로 이어받는다. 앞 편이 영상·강의를 따른 것이면 그 목차에 예고된 다음 주제를 후보로 사용자에게 고르게 한다.
- 바꾸는 곳: `eyebrow`(`PART 2. …`), 표지 `kicker`(`… · Part 2`)와 `part`(`Part 2.`), `brand.contact`(이번 편의 자료 기준), 섹션 `meta` 첫 줄(`Part 2. …`). 마무리 장은 `part: 'Next.'`로 다음 편을 잇는다.
- 파일 이름은 앞 편과 같은 접두어를 쓰고(예 `ai_intelligence_2026_…` → `ai_work_change_2026_…`), 허브 카드 제목에 `(Part 2)`, 설명 첫머리에 "○○ 후속편"을 적는다.
- 결론 한 줄(`take`)은 마침표로 끝나는 짧은 평서문으로 쓴다. 한국어 문장 끝에 콜론을 쓰지 않는다.
- `prefers-reduced-motion` 블록과 `<link rel="icon" href="data:,">`는 지우지 않는다.

## 5. 검증

```bash
python -m http.server 8765        # 작업 폴더에서 (이미 떠 있으면 생략)
python -I <스킬 폴더>/scripts/shoot.py http://localhost:8765/<파일명>.html <슬라이드수> <출력폴더>
```

- shoot.py에는 Playwright와 Chrome이 필요하다(`pip install playwright`).
- `Pretendard 웹폰트: OK`, `넘침: 0 건`, `줄바꿈 경고: 0 건`, `errors: []`가 나와야 한다.
  - 넘침은 화면 밖(가로 40~1880px, 세로 30~1030px — 하단 챕터 바 위) 이탈, 잘림, 자기 카드 폭 초과를 잡는다.
  - 줄바꿈 경고는 한 줄이어야 할 요소(카드 제목, 선택지 문장, 수치·라벨, 목차 항목, 섹션 제목)가 저절로 두 줄이 된 것을 잡는다. `<br>`로 일부러 나눈 요소는 제외한다. 문장을 줄이거나 의미 단위로 `<br>`을 넣는다.
- 캡처를 직접 열어 눈으로도 본다. 결론 줄이 출처 줄과 붙거나, 카드 높이가 들쭉날쭉한 것은 자동으로 잡히지 않는다.
- 외부 접속이 막힌 환경에서는 폰트 점검을 통과할 수 없으니 사용자에게 알린다.

## 6. 조작법

클릭, 스페이스, →, ↓는 다음 단계, ←, ↑는 이전 장이다. 하단 챕터 바를 누르면 그 챕터의 첫 장(섹션 장)으로 간다. 숫자를 치고 Enter를 누르면 그 장으로, G 키나 오른쪽 아래 카운터를 누르면 점프 창, F 키는 전체화면이다. 주소 뒤에 `#5`를 붙이면 5장으로 바로 열린다. `DECK.reveal`을 `'click'`으로 바꾸면 요소가 클릭할 때마다 하나씩 나타난다.
