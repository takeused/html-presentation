# Policy Briefing Presentation (정책 브리핑형 HTML 발표자료)

정부·공공·정책 주제 내용을 **정책 보고서 문법**(배경 → 진단 → 비전·전략 → 추진과제 → 이행관리 → 제언)에 맞춰 1920×1080 단일 HTML 덱으로 만드는 스킬입니다.

- 레퍼런스 완성본: `template.html` (국가 R&D × AI 정책 브리핑 15쪽). 새 덱은 이 파일을 복사해 내용과 데이터만 바꾸는 방식이 가장 빠릅니다.
- 외부 라이브러리 없음. 차트는 인라인 SVG, 폰트는 `assets/NanumSquare*.woff2`(없으면 Pretendard → 맑은 고딕으로 대체).

## 0. 핵심 원칙 — 레이아웃은 내용 유형이 정한다

이 스킬이 생긴 이유: 테슬라·NVIDIA 같은 **기업 브리핑 템플릿**(제품 스펙 세로 레버, 추론 경제학, 브랜드 필름, 고객 수요 분포)에 정책 내용을 끼워 넣으면, "로드스터 트림 선택" 레이아웃에 "AI 성숙도 Lv.1~3"이 들어가는 식으로 **형식과 의미가 어긋납니다.**

작성 순서는 반드시 아래와 같습니다.

1. 원문 내용을 슬라이드 단위로 쪼갠 뒤, 각 단위의 **내용 유형**을 먼저 판정한다 (아래 표).
2. 유형에 맞는 레이아웃 아키타입을 고른다. 템플릿의 기존 장 순서에 내용을 맞추지 않는다.
3. 장(Ⅰ~Ⅳ) 순서로 재배열한다.
4. 각 장 제목은 **헤드 메시지 한 문장**(결론)으로 쓴다. "~현황", "~개요" 같은 명사형 제목 금지.

| 내용 유형 | 판별 신호 | 레이아웃 아키타입 (template.html 클래스) |
|---|---|---|
| 핵심 수치 3개 + 주제 | 표지 | `cover` — 좌측 헤드라인·부제·흐름 칩·메타, 우측 네이비 KPI 패널 |
| 전체 요지 | "요약", 보고 첫 장 | `summary-wrap` — 배경→문제→전략→기대효과 4열 + 하단 KEY MESSAGE 띠 |
| 연도별 예산·투자 추이 | 3개년 수치, 부문별 금액 | `invest` — 그룹 막대(연도 선택) + KPI 3개 + 부문 표(선택 연도 열 강조) |
| 문제점과 개선 방향 | "기존", "한계", "병목" | `diag` — 병목 / As-Is / → / To-Be / 지표(전→후) 행렬 |
| 비전·목표·전략 | 정책 체계, 추진전략 | `frame` — VISION 띠 → 3대 목표(KPI) → 4대 전략 카드 → 추진 기반 |
| 단계 프로세스 | 탐색→기획→수행→평가 | `cycle` — 화살표로 연결된 단계 버튼 + 환류선 + 선택 단계의 As-Is/To-Be·추진내용·점검지표 3열 |
| 시스템 계층 | 데이터층·모델층·서비스층 | `arch` — 입력 데이터 | 아래→위 쌓인 계층 | 활용 주체 + 선택 계층 상세 |
| 작동 원리 (복수 엔진/기능) | "핵심 기술", "엔진" | `engines` — 3열 카드, 각 1→2→3 단계 + 정책 효과 + 적용 분야 (모달 금지, 한눈에) |
| 도입 단계·성숙도 | Lv.1~3, 1단계~3단계 | `maturity` — 계단형 막대(높이 = 고도화) + 선택 단계 상세 |
| 전후 비교 성과 | 단축률, 정확도, 배수 | `perf` / `multi` — 방식별 꺾은선·막대, 큰 성과 수치, 지표 전환 탭 |
| 재원 재배분 | 감액·증액·순증 | `portfolio` — 폭포(브릿지) 차트 + 100% 누적 막대 + 투자 축 카드 |
| 순환 구조 | 닫힌 루프, 피드백 | `sdl` — 3노드 원형 루프 + 단계 설명 + 확산 추이 막대 |
| 리스크·책임 | 점검 과제, 역할 분담 | `gov` — 번호 점검 카드 + "AI가 하는 일 / 사람이 하는 일" 대조표 |
| 결론 | 제언, 향후 과제 | `closing` — 번호 제언 3개 + 3개년 핵심 지표 표 + 참고자료 |

### 정책 덱에서 쓰지 않는 것 (기업 브리핑 잔재)

- 15초 모션그래픽 영상·브랜드 필름 장, "제작 안내" 장
- 제품 트림식 세로 레버, 슬라이드업 바텀 시트·드로어·센터 모달에 핵심 내용 숨기기 → 정책 보고는 **한 화면에 근거가 다 보여야** 함
- 마젠타·네온 등 마케팅 톤 컬러, 회전 궤도 같은 장식 비주얼
- 근거 없는 "중요도 점수" 같은 장식용 차트

## 2. 디자인 시스템

### 색 토큰 (`:root`)

| 토큰 | 값 | 의미 — 색은 반드시 의미로만 사용 |
|---|---|---|
| `--navy` | `#0e2747` | 구조·제목·비전 띠·최종값 |
| `--blue` | `#1d5fbf` | 주 데이터, 현재 선택, 강조 구절(`h2 mark`) |
| `--teal` | `#0a8f88` | To-Be, AI 적용 후, 증액, 개선 수치 |
| `--amber` | `#c9741c` | As-Is, 문제, 주의 각주(`.note` 왼쪽 선), 편집 모드 |
| `--red` | `#c2413b` | 감액·리스크 (폭포 차트 음수 등에만) |
| `--ink` / `--muted` / `--faint` | `#1d2433` / `#667085` / `#98a2b3` | 본문 / 보조 / 라벨 |
| `--line` / `--tint` | `#dde2ea` / `#eef3fa` | 구분선 / 패널 틴트 |

### 타이포그래피 (1920×1080 기준 px)

- 헤드 메시지 `h2` 46px/800, 핵심 구절만 `<mark>`(블루)
- 장 태그 `.tag` — `<em>Ⅲ-2</em>추진과제 · 핵심 AI 엔진`
- 카드 제목 22~32px, 본문 17~22px. **화면이 비어 보이면 여백을 늘리지 말고 글자를 키운다.** 본문 최소 16px.
- `word-break: keep-all` 전역 적용(어절 단위 줄바꿈).

### 프레임

- `#stage` 1920×1080 고정, `translate(-50%,-50%) scale(s)`로 창에 맞춤 → 어떤 해상도에서도 레이아웃 동일.
- 상단 바: 브랜드 · 장(Ⅰ~Ⅳ) 버튼 · 도구(글자 편집 / HTML 저장 / PDF 인쇄 / 전체화면)
- 하단 바: 현재 쪽의 `data-source` 출처 각주 · 쪽 번호 · 이전/다음 · 진행 막대

## 3. 인터랙션 규칙

- 인터랙션은 **선택하면 비교 대상이 바뀌는 곳에만** 넣는다 (연도, 단계, 계층, 성숙도, 지표, 투자 축, 루프 단계).
- 공통 탭 구조: 컨테이너 `data-tabgroup="이름" data-default="n"`, 버튼 `data-tab="i"`, 패널 `data-panel="i"`. 차트가 연동되면 `renderers[쪽 인덱스]`에서 `group.dataset.sel`을 읽어 다시 그림.
- 모든 패널을 숨겨도 뜻이 통하도록, 기본 선택(`data-default`)은 가장 대표적인 항목으로.
- 투자 축처럼 전체를 동시에 봐야 하는 목록은 `.keep` 클래스로 항상 표시하고 선택 항목만 강조.
- 진입 애니메이션은 `.rise`(순차 상승), 차트는 `.grow`/`.growx`/`.draw`. `prefers-reduced-motion` 존중, 첫 로드는 `#stage.init`으로 애니메이션 생략.
- 키보드: ←/→/PageUp/PageDown/Space/Home/End. URL `#n`으로 n쪽 바로 열기.

### 차트 헬퍼 (template.html 스크립트)

| 함수 | 용도 |
|---|---|
| `columns(host,{labels,series,max,fmt,tick,sel,unit})` | 세로 (그룹) 막대, `sel` 외 막대 흐리게 |
| `line(host,{labels,values,max,color,unit,hi})` | 꺾은선 + 영역, `hi` 지점 강조 |
| `hbars(host,{labels,values,max,colors,unit})` | 가로 막대 (방식별 배수 비교) |
| `waterfall(host,[{type:'total',v,label},{v:-1.2,label},…])` | 재원 브릿지 |

## 4. 데이터·문구 원칙

- **원문에 없는 수치·연도·기관명을 만들지 않는다.** 시점이 불명확한 단계는 "즉시 도입 / 확산 / 차세대"처럼 연도 없이 표기.
- 안(案)·목표치는 `2026(안)`, `(목표)`로 구분 표시.
- 같은 수치가 여러 장에 나오면 값이 일치하는지 마지막에 대조 (표지 KPI ↔ 요약 ↔ 체계도 목표 ↔ 성과 장 ↔ 결론 표).
- 쪽마다 `data-source`에 출처를 적는다. 원문 출처를 확인할 수 없으면 "검증 필요"를 사용자에게 알린다.
- AI·자동화 정책이면 "AI는 근거 제시, 결정·책임은 사람" 원칙을 거버넌스 장에 명시.

## 5. 작업 절차

1. 원문(기존 HTML·문서)에서 텍스트와 스크립트 속 데이터(차트 배열, 모달·시트 상세 문구)를 모두 추출한다. 모달·시트에 숨어 있던 상세 내용도 빠뜨리지 않는다.
2. §0 표로 내용 유형 판정 → §1 장 구조로 배치표 작성.
3. `template.html`을 복사해 쪽별 HTML·`data-source`·`budget`/`mult` 등 데이터 상수·`renderers` 인덱스를 교체.
4. 브라우저에서 모든 쪽을 열어 확인: 하단 넘침, 빈 공간 과다(→ 글자 확대), 패널 중복 표시, 수치 일치, 콘솔 오류.
5. 탭 클릭으로 연동 차트·KPI·표 강조가 함께 바뀌는지 확인.
